# Contributing

Спасибо, что хотите помочь! Это маленький, но чувствительный к безопасности
проект — пожалуйста, соблюдайте инварианты из `AGENT.md`.

## Процесс

1. Форкните репозиторий, создайте ветку от `main`:
   ```bash
   git checkout -b fix/describe-the-change
   ```
2. Внесите изменения. Для правок в самом релее (`tproxy-server/`) — это
   субмодуль: изменения идут в `telegramdesktop/tproxy-server`, здесь только
   обновляется закреплённый коммит.
3. Проверьте: `bash -n install.sh renew-cert.sh`, валидность YAML, при
   изменении образов — локальная сборка и smoke-тест (см. `AGENT.md`).
4. Откройте Pull Request с описанием: что менялось и почему, что проверено.

## Политика версий

- PR и мёрджи в `main` собирают dev-образы с хэшем коммита.
- Релиз = тег `v*` (`git tag v1.0.1 && git push origin v1.0.1`) — он собирает
  образы `<версия>` и двигает `latest`.
- `latest` обновляется только релизным тегом. Не коммитьте изменения тегов в
  workflow без необходимости.

## Что нельзя ломать

- host-сеть и loopback-ограничения релея (см. `AGENT.md`, п. 1);
- единый шлюз: nginx проксирует всё на релей, статикой не раздаёт;
- права на секреты и отсутствие логирования URI;
- фаервол-правила для 2398/8888;
- совместимость с x86_64 и официальным MTProxy (без форков).

## Стиль

- Коммиты на английском, сообщения по делу («why», не «what»);
- скрипты — bash с `set -euo pipefail`;
- изменения в `install.sh` должны сохранять идемпотентность повторного
  запуска (повторный запуск не должен менять секрет/домен/сайт/сертификат).
